## Repository Parameterization Analysis

This is a comprehensive mapping of how repositories are currently passed through the codebase layers. Key patterns to understand for the refactor:

1. **Most services receive multiple specific repos** - they explicitly depend on many repository types
2. **Application class holds repos as optional properties** but factory always passes them
3. **Workflows also receive specific repos** - they don't get an abstraction layer
4. **Database is always passed alongside repos** - sometimes both are needed
5. **Factories create repos then pass them to services** - tight coupling point

The refactor should likely:
- Create some kind of abstract access layer or repository manager
- Pass a single "data access" object instead of 5+ repos
- Keep Database instance separate (it's low-level)
- Or use a Service Locator pattern with the Application itself
